What Ryan fixes

Asks once, not always

At setup you answer yes, no or flexible for installs, commits, pushes, deploys and paid runs.

No "done" without proof

Reports only checks it ran, never weakens a failing test, and leaves a ticket open when a box is not verified.

Plans in one screen

About 10 questions with recommended answers, a one-screen spec, and tickets you can commit one by one.

Production safety rules

Asks before destructive migrations; tests never touch a real database, send real messages or move real money.

Security note: Ryan's guardrails are instructions to the agent, not runtime enforcement. They shape what the agent does but cannot guarantee it, and they do not replace sandboxing, permission settings or human review.

The flow

/ryan-wake-up     set this project up
/ryan-plan        a few questions, then a spec and tickets
/ryan-implement   build the next ticket (or 02, or all)
/ryan-status      what's next
/ryan-talk        just discuss, no spec
